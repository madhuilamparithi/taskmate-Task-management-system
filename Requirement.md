# TASKMATE – TASK MANAGEMENT SYSTEM
## Software Requirements Specification (SRS)

### 1. Introduction

**TaskMate** is a task management application designed to help users organize their daily activities, manage deadlines, prioritize tasks, and track task completion.

### 2. Project Scope

The system aims to provide a simple and user-friendly interface for managing personal tasks.

**Included features:**
- User Login and Sign Up
- Dashboard to view task summaries
- Add, Edit, and Delete Tasks
- Task priority and due date management
- Task status tracking
- Calendar view
- Profile and Settings

### 3. Functional Requirements

| ID | Requirement |
|---|---|
| FR01 | The system shall provide a login screen for users. |
| FR02 | The system shall provide a sign-up screen. |
| FR03 | The system shall allow users to create new tasks. |
| FR04 | The system shall allow users to edit existing tasks. |
| FR05 | The system shall allow users to delete tasks. |
| FR06 | The system shall allow users to set task priorities. |
| FR07 | The system shall allow users to assign due dates to tasks. |
| FR08 | The system shall display task status, such as Pending or Completed. |
| FR09 | The dashboard shall display a summary of tasks. |
| FR10 | The calendar shall display tasks according to their scheduled dates. |
| FR11 | The system shall provide profile and settings options. |

### 4. Non-Functional Requirements

1. **Usability:** The interface should be easy to understand and navigate.
2. **Performance:** Pages and task actions should respond within a reasonable time.
3. **Reliability:** The system should handle valid task operations consistently.
4. **Security:** Login information should be handled securely if authentication is implemented.
5. **Compatibility:** The application should work on commonly used modern web browsers.
6. **Maintainability:** The code should be organized so that future updates are easier.
7. **Responsiveness:** The interface should adapt to desktop, tablet, and mobile screens.

### 5. User Stories

| ID | User Story |
|---|---|
| US01 | As a user, I want to log in so that I can access the application. |
| US02 | As a user, I want to create tasks so that I can record my activities. |
| US03 | As a user, I want to edit tasks so that I can update task details. |
| US04 | As a user, I want to delete tasks so that I can remove unnecessary tasks. |
| US05 | As a user, I want to set priorities so that I can identify important tasks. |
| US06 | As a user, I want to set due dates so that I can manage deadlines. |
| US07 | As a user, I want to mark tasks as completed so that I can track my progress. |
| US08 | As a user, I want to view tasks on a calendar so that I can plan my schedule. |
| US09 | As a user, I want to view a dashboard so that I can understand my task progress. |

### 6. Project Constraints

- The project will be developed within the available academic schedule.
- Development will use the agreed-upon technologies: HTML, CSS, and JavaScript.
- GitHub will be used for version control and team collaboration.
- Features will be implemented according to the team's available time and resources.

### 7. Assumptions

- Users have access to a modern web browser.
- Users can provide the necessary information when creating a task.
- The team will confirm which features are supported by the final prototype.

### 8. Acceptance Criteria

The prototype will be considered acceptable when:

- The main application screens are available.
- Users can perform the task operations included in the prototype.
- Implemented features pass their relevant test cases.
- Known defects are documented.
- The README, requirements, workflow, wireframe, and test results are prepared for submission.

### 9. Conclusion

This requirements document defines the planned features, quality expectations, and user needs for TaskMate. It will guide the team's design, implementation, and testing activities.
